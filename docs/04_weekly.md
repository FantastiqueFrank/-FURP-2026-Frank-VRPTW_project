# 实验报告：PyVRP 与 OR-Tools 在 CVRP 上的性能对比

**实验者**：赵云龙 
**日期**：2026.7.4 
**实验环境**：Windows 11，Python 3.14.5，OR-Tools 9.15.6755，PyVRP 0.13.4，Intel Core i7，16GB RAM

---

## 1. 实验目的

本实验旨在对比两种常用的车辆路径问题（VRP）求解器——**PyVRP**（基于混合遗传搜索）和 **OR-Tools**（基于启发式与禁忌搜索）——在经典容量约束车辆路径问题（CVRP）上的性能表现。评估指标包括：

- 解的质量（目标值，即总行驶距离）；
- 求解时间；
- 与已知最优解的差距（gap）；
- 不同规模实例上的稳定性。

通过对比，我们希望了解哪种求解器更适合作为研究中的默认工具，以及各自的适用场景。

---

## 2. 实验设置

### 2.1 测试实例

使用来自 Augerat 数据集的 CVRP 标准实例：

| 实例名称 | 节点数（含仓库） | 客户数 | 最大车辆数 | 已知最优解 |
| -------- | ---------------- | ------ | ---------- | ---------- |
| A-n32-k5 | 32               | 31     | 5          | 784        |
| A-n55-k9 | 55               | 54     | 9          | 1073       |

两个实例分别代表**小规模**和**中等规模**，且具有公开的已知最优解，便于评估解质量。

### 2.2 求解器配置

#### PyVRP
- 版本：0.13.4
- 停止条件：`MaxRuntime(60)`（早期测试中使用），后改为 `MaxRuntime(5)` 和 `MaxIterations(5000)` 进行公平对比。
- 其他参数：默认，种子固定为 42。

#### OR-Tools
- 版本：9.15.6755
- 路由搜索参数：
  - 初始解策略：`PARALLEL_CHEAPEST_INSERTION`
  - 局部搜索元启发式：`GUIDED_LOCAL_SEARCH` / `TABU_SEARCH`（多次尝试）
  - 时间限制：60 秒（但实际提前终止）
- 其他参数：默认，未启用日志。

### 2.3 指标记录

- 目标值（总行驶距离）
- 实际使用的车辆数
- 运行时间（秒）
- 与已知最优解的百分比差距（gap%）

---

## 3. 实验结果

### 3.1 A-n32-k5（小规模，32节点）

| 求解器   | 目标值 | 车辆数 | 运行时间 (s) | 与最优解差距 |
| -------- | ------ | ------ | ------------ | ------------ |
| PyVRP    | 784    | 5      | 1.14         | 0.00%        |
| OR-Tools | 784    | 5      | 0.25         | 0.00%        |

**结论**：两种求解器均快速找到最优解，OR-Tools 略快。

### 3.2 A-n55-k9（中等规模，55节点）

| 求解器              | 目标值   | 车辆数 | 运行时间 (s) | 与最优解差距 |
| ------------------- | -------- | ------ | ------------ | ------------ |
| PyVRP               | **1073** | 9      | 1.92         | **0.00%**    |
| OR-Tools (默认)     | 1118     | 9      | 0.06         | 4.19%        |
| OR-Tools (延长搜索) | 1118     | 9      | 0.06         | 4.19%        |
| OR-Tools (GLS)      | 1110     | 9      | 0.27         | 3.45%        |

**观察**：
- PyVRP 在 1.92 秒内找到最优解 1073。
- OR-Tools 在所有尝试中均未达到最优，最佳结果为 1110（差距 3.45%），且运行时间极短（< 1 秒），表明其搜索策略在达到局部最优后过早收敛，即使给予更长时间（300 秒）也无法改进。

---

## 4. 分析与讨论

### 4.1 解的质量

| 实例     | PyVRP 最优 | OR-Tools 最优 | 差异          |
| -------- | ---------- | ------------- | ------------- |
| A-n32-k5 | 784        | 784           | 0%            |
| A-n55-k9 | 1073       | 1110          | 约 3.45% 差距 |

PyVRP 在两个实例上均达到已知最优，而 OR-Tools 在中等规模上出现显著差距，说明 PyVRP 的混合遗传搜索（HGS）具有更强的全局寻优能力，尤其适合规模稍大的问题。

### 4.2 求解时间

- OR-Tools 在 A-n55-k9 上仅用 0.06 秒，但解质量较低，表明其追求速度而牺牲质量。
- PyVRP 花费约 2 秒，但保证最优，在解质量和时间之间取得更好的平衡。

### 4.3 参数敏感性与稳定性

OR-Tools 对参数（如局部搜索元启发式、时间限制）调整不敏感，在 A-n55-k9 上未能通过调参改善解质量，可能因为其搜索算子的局限性。PyVRP 默认参数即可达到最优，说明其算法设计更为稳健。

### 4.4 适用场景建议

- **PyVRP**：适合对解质量有高要求的研究场景，尤其是中等规模及以上实例。其稍长的运行时间通常可接受。
- **OR-Tools**：适合快速获得可行解的场景，或作为其他方法的初始解生成器。对于小规模实例，其速度和精度兼备。

---

## 5. 结论

本实验通过对比 PyVRP 和 OR-Tools 在 CVRP 上的性能，得出以下结论：

1. **解质量**：PyVRP 在两个实例上均达到最优，OR-Tools 在中等规模实例上未能达到最优，差距约 3.5%。
2. **速度**：OR-Tools 极快（< 1 秒），但这是以牺牲解质量为代价；PyVRP 在 2 秒内仍能保证最优。
3. **稳健性**：PyVRP 的混合遗传搜索在默认参数下即表现优异，而 OR-Tools 的参数调优未能显著改善其在大规模实例上的表现。
4. **建议**：对于研究工作，PyVRP 是更可靠的选择；对于需要快速响应且对解质量要求不高的应用，OR-Tools 也可满足需求。

## 4. POMO 基线测试

### 4.1 测试脚本

使用 RL4CO 官方示例，在 TSP（旅行商问题）上验证 POMO 训练流程：

```python
from rl4co.envs.routing import TSPEnv, TSPGenerator
from rl4co.models import POMO
from rl4co.utils import RL4COTrainer

generator = TSPGenerator(num_loc=20, loc_distribution="uniform")
env = TSPEnv(generator)
model = POMO(env, batch_size=64, optimizer_kwargs={"lr": 1e-4})
trainer = RL4COTrainer(max_epochs=1, accelerator="gpu")
trainer.fit(model)
```

### 4.2 运行结果

| 指标             | 值          |
| ---------------- | ----------- |
| GPU 可用         | `True`      |
| 训练 Epoch       | 1           |
| 训练批次         | 1563        |
| 训练时间         | ~1 分 42 秒 |
| 平均奖励 (train) | -4.017      |
| 平均奖励 (val)   | -3.952      |

**结论**：POMO + RL4CO 框架在 TSP20 上成功运行，GPU 加速正常，环境配置正确。
