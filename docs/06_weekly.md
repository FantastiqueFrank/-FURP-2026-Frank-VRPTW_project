### 2.2 RL 扩展设计（Track C）

#### 2.2.1 MDP 形式化描述

将 EVRP-TW 建模为马尔可夫决策过程（MDP），为后续 POMO 训练提供理论框架。

##### State（状态）

当前时间步的状态由以下部分组成：
- **车辆位置**：当前所在节点（仓库 / 客户 / 充电站）
- **剩余电量**：当前电池剩余容量（kWh）
- **当前时间**：已累积时间（分钟）
- **当前载货量**：已装载量（kg）
- **已访问客户集合**：布尔向量，标记每个客户是否已服务
- **剩余需求集合**：每个客户尚待满足的需求量

##### Action（动作）

在每个时间步，模型从以下选项中选取一个动作：
- **访问一个未服务的客户**：需满足电量、时间窗、容量约束
- **前往一个充电站**：在电量不足时补充电量
- **返回仓库**：结束当前车辆的行程

##### Transition（状态转移）

执行动作后的状态更新：
- **位置**：更新为动作所选节点
- **电量**：减去行驶消耗；若访问充电站则增加充电量
- **时间**：增加行驶时间 + 服务时间 + 充电时间（如适用）
- **载货量**：若访问客户则减少对应需求
- **已访问集合**：标记客户为已访问

##### Reward（奖励）

- **即时奖励**：每一步的负行驶距离（鼓励短路径）
- **终端奖励**：若所有客户已访问，额外奖励 `0`；若违反约束（如电量耗尽），给予惩罚

##### Episode（回合）

- **起点**：车辆从仓库出发，满电、空载
- **终点**：所有客户服务完毕，车辆返回仓库
- **失败条件**：电量耗尽且无可用充电站，或时间窗无法满足

##### Terminal Condition（终止条件）

- 所有客户均已访问
- 当前车辆无法执行任何合法动作（无可行下一步）

#### 2.2.2 评估指标

- 总行驶距离（目标值）
- 可行性（是否满足所有约束）
- 平均奖励（训练曲线）
- 与 OR-Tools 基线的差距

#### 3.2.2 对比方法

| 方法                 | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| OR-Tools（默认参数） | 初始解：`PARALLEL_CHEAPEST_INSERTION`，局部搜索：`TABU_SEARCH`，时间限制：60s |
| OR-Tools（质量优先） | 同上，时间限制：300s                                         |
| PyVRP（默认）        | `MaxRuntime(60)`，种子固定为 42                              |

#### 3.2.3 评估指标

- 目标值（总行驶距离）
- 运行时间（秒）
- 与已知最优解的差距（gap%）
- 可行性（是否可行）
- 实际使用的车辆数

#### 3.2.4 预期结果

- PyVRP 在大部分实例上能找到比 OR-Tools 更优的解（gap 更小）。
- OR-Tools 在时间限制内返回速度更快，但解质量可能较低。
- 整合后的评估框架能自动生成结果表格，减少手动整理工作。

### 3.3 失败场景预期

- OR-Tools 可能在部分实例上因局部最优而无法进一步改进。
- PyVRP 在更大规模（100+ 客户）实例上运行时间可能显著增加。
- 如果实例的时间窗或电池约束过紧，可能导致无可行解。
